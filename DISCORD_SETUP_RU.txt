MOPS PARCEL — ПОДКЛЮЧЕНИЕ ЛЕНТЫ DISCORD

Что добавлено:
- Вкладка «Парсер» для подтверждённых клиентов и администратора.
- Карточки с названием, ценой, фотографией и ссылкой, поиск, страницы.
- Кнопка «Парсер» и команда /parser в Telegram.
- RU / UK / EN, защита от дублей и обработка ошибок доступа/лимитов Discord.
- Администратор видит подсказку о причине ошибки. Токен не показывается пользователям.

1. ЗАГРУЗКА
Обновите исходники в существующем GitHub-репозитории содержимым архива.
Ничего предварительно удалять не нужно. Не загружайте .env, .venv, SQLite и uploads.
Сохраните прежние ENV, базу, фотографии и настройки сайта.
Новых Python-библиотек не требуется. Команда запуска Render остаётся прежней.

2. DISCORD-БОТ
Откройте https://discord.com/developers/applications и создайте приложение.
В разделе Bot получите токен бота и включите Message Content Intent.
Токен должен быть именно Bot Token — не webhook URL, не Public Key и не токен личного аккаунта.
В Installation включите Guild Install со scope bot.
Дайте только View Channels и Read Message History.
Используйте установочную ссылку, чтобы добавить бота на сервер с вашим каналом.
Для добавления требуется Manage Server; если у вас нет этого права, попросите администратора сервера.
В приватном канале отдельно разрешите боту View Channel и Read Message History.
Разрешение Administrator и отправка сообщений для этой интеграции не нужны.
Существующий webhook чужого парсера оставьте как есть.

3. ID КАНАЛА
В Discord включите Developer Mode (Настройки пользователя → Расширенные).
Нажмите правой кнопкой по каналу, куда webhook публикует объявления → Copy Channel ID.
Это числовой идентификатор, не название #канала и не ссылка webhook.

4. RENDER → ENVIRONMENT
Добавьте две переменные:
DISCORD_BOT_TOKEN=токен_вашего_Discord_бота
DISCORD_CHANNEL_ID=числовой_ID_канала

При необходимости можно ограничить сообщения одним webhook:
DISCORD_WEBHOOK_ID=числовой_ID_webhook
Эта переменная необязательна. Без неё читаются сообщения всех webhook в выбранном канале.
Обычные сообщения людей не публикуются в Mops Parcel.

Сохраните ENV и выполните Deploy. Откройте /parser в Mops Parcel.
Администратор увидит подробную подсказку, если Discord отклоняет запрос.
Платный Render Shell для подключения Discord не нужен.

5. TELEGRAM
Отправьте /start: появится кнопка «Парсер». Команда /parser работает после обновления кода.
Чтобы она появилась также в списке команд Telegram, повторно запустите локально:
.\.venv\Scripts\python.exe .\configure_telegram.py
Локальный .env для этой команды должен содержать настройки Telegram и HTTPS-адрес сайта.
При переходе из Telegram действует обычный вход в Mops Parcel и одобрение аккаунта.

КАК РАБОТАЕТ ОБНОВЛЕНИЕ
Сайт обращается к Discord API от имени бота при открытии ленты, затем раз в минуту,
пока вкладка видима. Это чтение канала через API, не непрерывный Gateway-процесс.
Нажатие «Обновить» использует общий минутный кеш: каждый клиент не создаёт отдельный поток запросов.
Если все закрыли ленту, постоянного фонового чтения нет. Следующее открытие продолжает загрузку.
На первом подключении импортируются до 100 последних сообщений, не вся история канала.
Далее загружается до 100 новых сообщений за обновление. Большая очередь догружается постепенно.
Редактирования и актуальные ссылки фотографий сверяются для последних 100 сообщений.
Старые картинки Discord могут истечь; доступна ссылка на оригинал сообщения.
Удаление/продажа товара у источника не удаляет автоматически сохранённую карточку.
Содержимое объявлений не переводится: переводятся элементы интерфейса.
Распознавание рассчитано на типичные текстовые сообщения и embeds: title, description,
fields с Price/Цена/Ціна/Cena, image/thumbnail и вложения. Один пост — одна карточка.
У сложного формата парсера могут потребоваться дополнительные правила разбора.
Изображения отображаются только с Discord CDN и распространённых доменов Vinted/eBay/Grailed/Depop.
Произвольные сторонние серверы изображений не запрашиваются.

О ДАННЫХ
Этот модуль добавляет две таблицы и не удаляет аккаунты, заказы или фото.
Он НЕ устраняет известную проблему потери SQLite при пересоздании непостоянного диска.
Для постоянного хранения аккаунтов по-прежнему требуется постоянное хранилище
или отдельная миграция проекта на внешнюю базу данных.
При потере кеша парсера заново импортируются последние 100 сообщений Discord.

ПРОВЕРКА
Автоматические тесты используют имитацию Discord API и временные SQLite-базы.
Реальное подключение требует вашего Discord-бота, доступа к каналу и ENV.
Сайт/бот не публикует ничего в Discord и не меняет сообщения источника.
